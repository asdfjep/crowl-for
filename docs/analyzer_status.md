## 一、项目概览

AI News Analyzer 是一个独立的新闻分析服务，接收爬虫模块推送的 JSON 数据，执行 **去重 → 事件聚类 → 评分 → 板块分类 → 报告生成** 的完整流水线。提供 FastAPI 服务（8011 端口）和本地 `run.py` 两种运行方式。

### 目录结构

```
ai-news-analyzer/
├── services/
│   ├── __init__.py              # 空文件，包标识
│   ├── analyzer.py              # 分析入口，串联整个流水线
│   ├── deduplicator.py          # 三级去重 + 事件聚类
│   ├── news_scorer.py           # 多维度评分引擎
│   ├── board_classifier.py      # 21个细分板块分类器
│   ├── report_generator.py      # Markdown 报告生成器
│   └── coordinates.py           # 地点→经纬度坐标映射表
├── data/                        # 接收的原始 JSON 数据
├── reports/                     # 生成的 Markdown 报告
├── server.py                    # FastAPI 服务
├── run.py                       # 本地运行入口
├── Dockerfile
├── requirements.txt
└── README.md
```

## 三、评分引擎（news_scorer.py）分析

### 3.1 评分维度结构

```
总分 = (关键词*0.25 + 地理*0.15 + 板块*0.15 + 时间*0.15 + 标题*0.10 + LLM*0.20) * 4
```

各维度原始分范围：
- 关键词: 0-100+（匹配到的关键词权重累加，无上限）
- 地理: 0-15（取最高匹配地理权重）
- 板块: 0-13（CATEGORY_BASE_WEIGHT * 10，最大1.3*10=13）
- 时间: 0-15（24h半衰期指数衰减）
- 标题: 0-10
- LLM: **固定 10.0**（预留，未实际接入）

### 3.2 权重配置存在的问题

| 问题 | 严重度 | 说明 |
|------|--------|------|
| **LLM 维度硬编码** | 🔴 高 | `llm_score = 10.0` 固定值，占 20% 权重。相当于所有新闻白拿 2 分（10×0.20×4=8），失去区分度 |
| **归一化逻辑混乱** | 🔴 高 | 加权后 `*4` 的归一化因子缺乏数学依据。假设各维度取均值，加权后约 17.5 分，×4 = 70 分。实际分数分布集中在 20-50 分区间 |
| **关键词无上限累加** | 🟡 中 | 标题包含多个高权重词时得分快速膨胀。如 "首次发射火箭导弹" = 8+6+9 = 23 分，容易拉开不合理差距 |
| **地理权重取值偏颇** | 🟡 中 | 使用 `max()` 只取最高地理权重而非累加。一条新闻同时提到"中国"和"美国"不会加分，只取最高值 |
| **时间衰减过快** | 🟡 中 | 24h 半衰期意味着 48h 前新闻仅得 3.75 分（15×0.25），对跨日追踪不友好 |
| **板块权重差距过小** | 🟢 低 | CATEGORY_BASE_WEIGHT 从 0.9 到 1.3，差异仅 44%，区分度有限 |

### 3.3 实际评分分布（基于 2026-04-15 数据）

- 最高分：71 分（以色列袭击黎巴嫩）
- TOP 10 分数范围：43-71 分
- 大量新闻集中在 18-35 分
- **评分区分度不足**：284 条新闻中，绝大多数分数差距在 10 分以内

### 3.4 结论

权重配置**基本可用但不够精细**。主要问题在于 LLM 维度形同虚设、归一化因子随意、以及评分结果区分度不足。建议去除硬编码的 LLM 分数，重新校准权重比例。

## 四、板块分类器（board_classifier.py）分析

### 4.1 板块覆盖范围

共 **20 个细分板块 + 1 个兜底**，归入 6 大父板块：

| 父板块 | 细分板块 | 关键词数 |
|--------|----------|----------|
| **航空航天** (5) | launch, deep_space, commercial_space, space_station, space_policy | 8-10 个/板块 |
| **AI** (5) | model_release, ai_research, ai_regulation, ai_industry, ai_application | 8-10 个/板块 |
| **显示技术** (4) | oled, lcd_panel, polarizer, display_equip | 5-8 个/板块 |
| **财经** (4) | earnings, capital_market, ma, market_trend | 6-8 个/板块 |
| **军事冲突** (3) | combat, weapons, diplomacy | 6-7 个/板块 |
| **综合** (2) | general_tech, other（兜底） | 8 个 / 0 个 |

### 4.2 覆盖范围评估

| 维度 | 状态 | 说明 |
|------|------|------|
| **项目核心领域** | ✅ 良好 | 航空航天（5板块）、显示技术（4板块）覆盖充分 |
| **AI 领域** | ✅ 良好 | 涵盖模型发布、研究、监管、产业、应用 |
| **军事/政治** | ⚠️ 不足 | 仅 3 个板块，缺少地缘政治、经济制裁等独立分类 |
| **板块分类** | ⚠️ 问题 | `politics` 类别回退到 `diplomacy`（外交制裁），但政治新闻不等同于外交新闻 |
| **兜底机制** | ⚠️ 粗糙 | `other` 板块关键词为空，纯靠回退映射 |
| **分类方法** | ⚠️ 简单 | 纯关键词匹配，无语义理解，存在误分类风险 |

### 4.3 实际分类问题（来自报告样本）

1. **军事冲突 → 武器装备** 板块下出现了阿里云游戏、迈威生物临床试验、百度Create大会等完全不相关的新闻
2. **技术突破** 板块下出现了 "商务部消费品以旧换新" 等财经新闻
3. **"发布"** 关键词过于宽泛，同时存在于 model_release 和多个板块，容易误分类
4. **"中国"** 新闻被分类到多个板块，但地理热力图只显示 "中国: 100条"，粒度太粗

### 4.4 结论

板块定义**对核心领域覆盖良好**，但分类算法过于简单（纯关键词匹配），且存在明显的误分类问题。建议增加语义分类能力或优化关键词体系。

## 五、报告生成器（report_generator.py）输出质量分析

### 5.1 报告结构（6个板块）

| 板块 | 内容 | 质量 |
|------|------|------|
| 🏆 TOP 10 重大事件 | 评分排序 + TOP 5 详情 | ✅ 结构清晰，信息完整 |
| 📌 重点板块排名 | 航空航天/AI/显示技术 TOP 5 | ✅ 有统计摘要和占比分析 |
| 📊 板块分布摘要 | 所有父板块下的细分板块 TOP 3 | ✅ 覆盖全面 |
| 📍 地理热力 | 地点 + 新闻数 + 坐标 | ⚠️ 代表性新闻与地点不匹配 |
| ⏱️ 24h 时间线 | 按小时分组的事件列表 | ✅ 实用 |
| 📡 数据源质量评估 | 各数据源新闻统计 | ⚠️ 评估维度不够深入 |

### 5.2 输出质量问题

| 问题 | 严重度 | 说明 |
|------|--------|------|
| **地理热力代表性新闻错误** | 🔴 高 | "中国" 的代表性新闻是以色列袭击黎巴嫩，明显不匹配。原因是 location 字段与新闻内容不一致 |
| **军事板块分类污染** | 🔴 高 | "武器装备" 板块出现AI/医疗新闻，严重影响报告可信度 |
| **事件聚类效果差** | 🔴 高 | 284 条新闻产生 276 个簇，几乎每条新闻一个簇。聚类阈值 0.5 过严，失去"聚合报道"的意义 |
| **数据源评估缺少独特性** | 🟡 中 | `unique_count` 统计逻辑有问题（没有真正去重），实际只是计数 |
| **报告体积过大** | 🟡 中 | 单次报告 4361 行 / 165KB，包含完整 JSON 附录。在 Markdown 渲染中性能不佳 |
| **缺少可视化** | 🟡 中 | 纯文本表格，缺少图表/趋势线等可视化元素 |
| **时间线仅展示高评分** | 🟢 低 | 时间线只展示 clusters 中的事件，不包含独立新闻 |

### 5.3 结论

报告**结构完整、可读性好**，但受限于上游（聚类、分类）的质量问题，部分内容可信度存疑。地理热力和军事分类的错误最为明显。

### 6.3 API 设计缺陷

| 问题 | 严重度 | 说明 |
|------|--------|------|
| **缺少认证机制** | 🔴 高 | 无任何鉴权，任何人均可调用分析接口 |
| **无速率限制** | 🟡 中 | 未配置 rate limiting，容易被滥用 |
| **report_path 始终为空** | 🟡 中 | `AnalyzeResponse` 返回 `report_path`，但 `ReportGenerator` 从未设置此字段 |
| **缺少分页** | 🟡 中 | `/api/reports` 硬编码返回前 50 个，无 offset/limit 参数 |
| **无批量/增量分析** | 🟡 中 | 每次必须提交完整新闻列表，不支持增量更新 |
| **缺少 CORS 配置** | 🟢 低 | 如果前后端分离部署，需要 CORS 中间件 |
| **无 OpenAPI 文档定制** | 🟢 低 | 使用默认 FastAPI 文档，缺少示例和描述 |

## 七、改进建议（按优先级排序）

### 🔴 P0 — 修复事件聚类阈值，提高聚合效果

**问题**：284 条新闻产生 276 个簇，聚类几乎无效。

**具体改进**：
1. 降低 `cluster_threshold` 从 `0.5` 到 `0.25-0.3`
2. 在 `_belongs_to_cluster()` 中引入加权重叠度：核心实体（人名、机构、地点）匹配权重加倍
3. 增加二次聚类：首轮宽松聚类后，对大簇进行二次精炼
4. 添加 `max_cluster_size` 限制，防止单个簇包含过多无关新闻

**影响范围**：`deduplicator.py`, `analyzer.py`

---

### 🔴 P0 — 修复评分引擎，提升区分度

**问题**：LLM 硬编码 10 分、归一化因子随意、评分区分度不足。

**具体改进**：
1. **移除硬编码 LLM 分数**：将 LLM 维度权重降至 0 或设为可配置默认值 0
2. **重新分配权重**：关键词 35%、地理 15%、板块 10%、时间 20%、标题 10%、多源覆盖 10%
3. **关键词得分改为 Top-K 累加**：取匹配到的前 N 个最高权重关键词累加（而非全部），避免膨胀
4. **时间衰减改为线性+指数混合**：0-6h 满分，6-24h 线性衰减，24h+ 指数衰减
5. 增加 **多源覆盖** 作为独立评分维度（已在 cluster 评分中实现，但单条新闻没有）

**影响范围**：`news_scorer.py`

---

### 🟡 P1 — 修复板块分类器误分类问题

**问题**：军事/技术板块混入不相关新闻，分类可信度低。

**具体改进**：
1. **增加分类置信度**：关键词匹配数达到阈值才分类，否则 fallback
2. **优化冲突关键词**：
   - 将 "发布" 从 model_release 中移除或限定上下文
   - 增加负向关键词列表（如 "发布" 出现在 "财报发布" 时应归入财经）
3. **增加父子板块两级校验**：先匹配父板块，再在父板块下细分，减少跨领域误分类
4. **修正 politics → diplomacy 映射**：新增 `politics_general` 板块或拆分 diplomacy
5. **引入简单 NLP**：使用 jieba 词性标注，优先匹配名词/专有名词

**影响范围**：`board_classifier.py`

---

### 🟡 P1 — 完善 API 安全性与功能

**问题**：无认证、无速率限制、report_path 为空。

**具体改进**：
1. **添加 API Key 认证**：使用 `fastapi.security.APIKeyHeader`，简单有效
2. **添加速率限制**：使用 `slowapi` 或自定义中间件，限制 10 次/分钟
3. **修复 report_path**：在 `ReportGenerator.generate_daily_report()` 中返回生成的文件路径
4. **添加分页参数**：`/api/reports?offset=0&limit=20`
5. **添加 `/api/analyze/batch`**：支持批量提交多日数据
6. **CORS 中间件**：添加 `CORSMiddleware` 配置

**影响范围**：`server.py`

---

### 🟢 P2 — 优化报告输出质量

**问题**：地理热力代表性新闻不匹配、报告体积过大、缺少可视化。

**具体改进**：
1. **修复地理热力**：使用新闻的 location 字段直接匹配，不再用标题作为代表性新闻
2. **精简 JSON 附录**：只保留 summary 和 TOP 10，完整数据改为可选下载接口
3. **增加报告元数据**：在报告头部增加分析耗时、数据质量评分等指标
4. **增加趋势对比**：与昨日报告对比，标注新增/消失的热点事件
5. **地理热力增加可视化**：生成简单的 ASCII 热力图或输出 GeoJSON 供前端渲染

**影响范围**：`report_generator.py`, `server.py`

## 八、总结

AI News Analyzer 整体架构**清晰合理**，流水线设计（去重→聚类→评分→分类→报告）符合新闻分析的最佳实践。代码质量良好，模块化程度高。

**主要优势**：
- 三级去重机制设计完善
- 报告结构丰富，包含 6 个维度的分析
- API 设计有基本的安全意识（路径穿越防护）
- 支持多种运行方式（本地/API/Docker）

**核心短板**：
- 事件聚类阈值过严，导致聚类效果几乎为零
- 评分引擎 LLM 维度硬编码、归一化不科学
- 板块分类器纯关键词匹配，误分类明显
- API 缺少认证和速率限制

**建议优先处理 P0 级别的聚类和评分问题**，这两项改善后将显著提升整体分析报告的质量。
